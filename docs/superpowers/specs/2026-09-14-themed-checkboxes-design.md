# 随便签主题变化的待办框

## 已确认方向

未完成不填色，保留清晰描边；已完成采用随便签主题变化的低饱和浅色填充，勾号保持清晰。只改变外观，不改变勾选、Markdown 编辑、保存、撤销和删除线行为。

## 配色与范围

- 未完成填充为透明色，不再使用正文颜色的 8% 填充。描边沿用现有 1.5 点宽度及适配浅色、深色便签的正文色描边。
- 已完成按便签主题配色，而非系统强调色：纸白用浅暖灰，雾蓝用浅灰蓝，薰衣草用浅灰紫，暖黄用浅米黄，石墨用浅中性灰。
- 浅色填充通过低饱和颜色本身实现，不跟随背景透明度淡化。勾号使用与浅填充有明显对比的深色，不直接沿用石墨主题的白色正文。
- 不改变待办框的尺寸、圆角、描边宽度和点击范围。不添加新的设置选项。
- 背景透明度为 0%、50%、100% 时，待办框自身的绘制颜色保持一致；全透明时桌面仍可能影响未完成空心框的对比度，不承诺在任意底图上都一样清晰。

## 当前实现与修改边界

`StarMemoMarkdownThemeFactory` 已能配置未完成框的填色与描边，但已完成框的薄荷绿和勾号颜色写死在 MarkdownEngine 的 `MarkdownTextLayoutFragment` 绘制逻辑中。

在引擎主题中新增可配置的已完成填充和勾号颜色，默认保留引擎原来的颜色，避免影响其他调用者；StarMemo 使用自己的五套主题配色覆盖。更新内置引擎修改记录，不引入新依赖，不重写编辑器。

## 验收

1. 配置测试先证明旧代码未完成填色不透明、完成色不可随主题改变，再验证修复后的五套主题映射。
2. 用生产编辑器绘制五种便签主题的未完成和已完成框，检查截图，不只验证颜色配置对象。
3. 在同一张便签中切换主题，验证已有任务框立即更新，无需重开，且不丢失正文、选区和撤销记录。
4. 验证背景透明度不会把框和勾号一起淡化；验证点击任务框仍正确切换 Markdown 的 `[ ]` 与 `[x]`。
5. 运行完整核心和 UI 回归。通过后生成新编号本地安装包，不覆盖既有 0.1.5，不自动安装或上传 Release。
