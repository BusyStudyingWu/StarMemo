# StarMemo 全局设置与透明度

## 已确认的方向

设置页只保留一组：颜色、透明度、字号、置顶。修改立即作用于所有已打开的便签，保存后供后续新建及重新打开的便签使用。不再显示“当前便签”和“新建默认值”两组。

## 透明度的准确含义

- 标签直接写“透明度”。范围 0%–100%，0% 完全不透明，100% 隐去背景。
- 背景不透明度直接等于 `1 - 透明度`，取消原来 65%–100% 被重新映射为 82%–100% 的对比度下限。
- 只调整背景层；颜色底层和磨砂层作为同一背景处理，不能留下一层不随滑块变化的底板。
- 正文、待办框及操作控件不跟随背景淡化；不修改整个窗口的 alpha。透明背景下的复杂桌面可能影响阅读，这是用户主动调整透明度的取舍，不再通过隐藏数值限制回避。
- 系统开启“减少透明度”时，背景暂时不透明，滑块置灰并显示原因；保留原设置，系统关闭该选项后恢复。

## 状态与兼容

- AppSettings 保存统一设置，窗口协调器将变更广播给已有窗口，并让新建和恢复窗口使用同一份设置。
- 全局颜色、透明度和置顶变更不能仅更新设置页数字；必须触达原生窗口和实际渲染层。字号沿用已有实时更新方式。
- 标题栏现有调色板、图钉继续作为单张便签快捷操作；下一次修改对应全局选项时，覆盖所有便签的该选项。设置页不再追踪最近活动便签。
- 旧透明度数据按旧渲染公式换算为新值，仅在一次性迁移时使用，尽量保留升级时的背景外观；运行时不再采用隐藏映射。
- 首次升级以原全局默认设置初始化统一设置。旧的单张颜色、背景和置顶偏好不再覆盖全局设置；正文、文件位置、窗口位置、恢复内容不变。

## 验收

1. 同时打开至少两张便签，修改每个全局选项，验证两张都立即更新；再新建、关闭重开，验证继承正确。
2. 检查透明度 0%、50%、100% 的真实背景变化；确认文字、待办框和控件未一起淡化，不只断言状态数字。
3. 验证系统“减少透明度”开启和关闭时的滑块状态、原因提示、背景效果以及原值恢复。
4. 验证旧设置迁移只执行一次，不修改 Markdown 正文。
5. 回归标题改名、拖动、编辑焦点、保存退出和全局字号；实际无法验证的系统行为单独注明，不以单元测试代替。

## 范围与工作状态

- 不改 Markdown 引擎，不新增其他设置，不更改用户的真实便签。
- 本轮只记录规格；实施后生成新的本地候选安装包，不自动安装、启动正式应用或上传 Release。
- 已完成：代码与录屏排查、方案比较、交互方向确认、规格自查。
- 待完成：用户复核规格、编写实施计划、测试先行实现、回归验收与打包。
